# 다른 데이터셋 확장 사전 기준 (2026-11-22)
**CIC-IoT-2023 결과는 "인위적 비IID(KMeans 군집 분할; 기기 식별자 없음, 자연 비IID 아님)" 한계를 첫 줄에 명시해 보고한다.**

목적: N-BaIoT에서 통과한 MSEAvg(D0) vs MSEAvg+모멘텀(D1, β=0.9, η=1; 가중 동일=역MSE) 비교가 ToN-IoT·CIC-IoT-2023에서도 유지되는지 확인. 데이터셋·분할별로 따로 보고하며 합치지 않는다.

## 데이터·전처리 (dataset_adapter.py)
- 공통: 클라이언트별 StandardScaler(train 적합), 정상 행을 셔플해 train 40/valid 10/dev 30/test 20 분할, dev는 클라이언트당 300행 상한, 공격 풀은 모든 클라이언트 공통 test에 추가. 모델 구조는 FedMSE와 동일(SAE hidden 50·latent 11, CEN 분류기), 입력차원만 데이터에 맞춤, 라운드당 참여 50%(ToN 4/8, CIC 5/10).
- ToN-IoT: train_test_network.csv, mitm 제외, 클라이언트=정상 행 1500개 이상인 src_ip 호스트 8개, 특징은 기존 'flow' 세트(33차원), 호스트당 정상 행 3750 상한, 공격은 유형당 1000행(전체 8000행). 클라이언트 순서·분할은 data_seed로 결정.
- CIC-IoT-2023(`cic_km`, 주 판정): 정상 40만 행 부분표본을 KMeans 10군집(data_seed)으로 분할=클라이언트, 클라이언트당 정상 3000행 상한(군집이 작으면 그 이하), 공격은 31종×200행. 군집 크기 불균형으로 train이 매우 작은 클라이언트가 생길 수 있음(인위 분할의 특성, 제외하지 않음).
- CIC IID(`cic_iid`, 참고): 같은 데이터를 무작위 10등분. 판정에 쓰지 않음.
상한(3750·3000)은 연산량 때문이며 결과를 본 뒤 바꾸지 않는다.

## 실행 (사전 고정, 결과 보고 수정 금지)
D0=variant `mse`, D1=variant `mse_m`. parallel, lr=1e-5, 40라운드, patience=3, batch=12, 최대 100 epoch, 두 방법의 참여 순서 동일(사후 검증).
- ton: data_seed 1234, 2024 × run 10–19(10런) × 2방법
- cic_km: data_seed 1234, 2024 × run 10–19(10런) × 2방법
- cic_iid(참고): data_seed 1234 × run 10–14(5런) × 2방법
총 90런. 시드=run×10000.

## 주 지표·판정
데이터셋·data_seed 셀마다 따로: 런별 R31~R40 클라이언트 평균 AUC의 평균의 짝차 D1−D0, 양측 95% t 구간. 통과 = 해당 셀의 하한 > +0.3%p. 데이터셋 판정: 해당 데이터셋의 두 data_seed 셀이 모두 통과해야 "통과", 하나만 넘으면 "부분", 아니면 "불통과". 발산(R5 이후 평균 AUC<0.90)은 제외하지 않고 포함·별도 집계. 보조: R20/R40 짝차, 0.97 유지 도달 라운드(미도달 수), 학습 스텝 총합. 결과 후 설정·기준 변경 금지(DEVIATIONS_dataset.md에 기록).

## 한계
N-BaIoT와 달리 모델 하이퍼파라미터(hidden 50, latent 11, lr 1e-5)를 데이터셋에 맞춰 조정하지 않았다. ToN은 호스트 8개·정상 소량, CIC는 인위 분할. data_seed 2개.
