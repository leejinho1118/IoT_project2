# 손해/이득 클라이언트의 데이터 특성 점검 (2026-11-24) — 탐색·사후, 신규 학습·실행 없음, 기존 데이터만
이전 동결 문서는 수정하지 않는다. 작성자는 클라이언트별 이득·손해의 대략적 분포(ToN은 약한 클라이언트가 크게 손해, N-BaIoT는 약한 클라이언트가 이득; RESULTS_why1.md)를 이미 보았으나, 어느 클라이언트가 누구이며 그 데이터 특성이 어떤지는 아직 보지 않았다.

## 분석 대상
- 셀: ToN data_seed 1234·2024, CIC-km 1234, N-BaIoT 1234·2024·4321·7777. 클라이언트별 D1−D0(10런 짝평균, R31~40 클라이언트 AUC)과 D2−D0(run 10 한 런). 클라이언트 식별은 로그의 `devices` 이름(ToN=src_ip, N-BaIoT=Client-k, CIC=cic순서가 data_seed별 군집 순서라 군집 번호를 재현해 매핑; 재현 불가 시 CIC는 제외하고 사유 기록).
- 손해군 = D1−D0 하위 3 클라이언트, 이득군 = 상위 3(ToN은 이득군이 없으면 손해 정도가 가장 작은 3). 나머지 = 중간군.

## 클라이언트 특성(기존 원본 데이터에서 계산, 학습 없음)
- P1 정상 샘플 수(상한 적용 전 원본 행 수와 상한 적용 후 train 크기).
- P2 특징 이동: 전체 정상 풀 표준화(풀 평균·표준편차) 후 클라이언트 평균 벡터의 풀 평균으로부터의 유클리드 거리.
- P3 공격 분리도: 클라이언트 자체 train 스케일러로 표준화한 공격 행들의 특징별 |z| 평균의 중앙값(클수록 이상이 쉽게 보임). N-BaIoT는 클라이언트별 abnormal 파일을 사용.
- P4 공격 구성: ToN·CIC는 모든 클라이언트가 같은 공격 풀을 공유(설계상 차이 없음, 구성 동일임을 기록). N-BaIoT는 클라이언트별 abnormal 행 수·정상 대비 비율.
- P0 기준선 난이도: D0 클라이언트 AUC(R31~40).

## 사전 패턴
- "데이터 특성 설명 지지": 데이터셋의 모든 셀에서 같은 부호로, 클라이언트별 D1−D0와 어떤 특성(P1~P4) 사이 스피어만 |ρ| ≥ 0.7, 그리고 손해군의 특성 값 범위가 이득군(또는 중간군)과 겹치지 않음(최소~최대 구간이 안 겹침).
- 클라이언트 수가 8~10이라 |ρ|≥0.7도 우연일 수 있다(예: n=8에서 p≈0.05). 여러 특성을 동시에 보므로 다중비교로 해석한다(지지 판정이 아닌 "단서"로 표기).
- 모든 특성이 |ρ|<0.5이면 "데이터 특성 설명 불지지", 그 사이는 "구분 불가".
- 임계(0.7, 0.5, 3개)는 관례값, 결과 후 변경 금지.

## 한계
클라이언트 8~10개, 특성 선택이 임의적(P1~P4만), 상관은 인과 아님, D2는 n=1 런, 중간 계산(전처리)을 재현하는 과정의 오차 가능. 결과 후 설정 변경 금지.
