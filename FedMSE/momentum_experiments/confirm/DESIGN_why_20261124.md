# 왜 모멘텀 이득이 N-BaIoT에서만 나는가 — 원인 분석 설계 (2026-11-24) — 탐색·사후(post-hoc), 실행 전 설계 문서
이전 동결 문서는 수정하지 않는다. 작성자는 지금까지의 모든 결과(D1·D2·걸음 맞춤·방향 로깅)를 이미 본 뒤 가설을 세웠으므로 아래 가설은 사후 가설이며, 지지 여부는 확증이 아니다. 용어 정정: 이득이 나는 쪽은 모멘텀(D1·D2), 기준선은 MSEAvg(D0). "MSEAvg가 이긴다"가 아니라 "모멘텀이 N-BaIoT에서만 D0를 이긴다"가 질문이다.

## 지금까지 관찰(가설의 출발점, 새 근거 아님)
N-BaIoT: D0는 1라운드부터 AUC가 ~96% 정체, D1·D2 모두 +1~+3%p, 클라이언트 간 정렬 높음(E≈0.85). ToN: D0는 초반부터 ~97%, D1 붕괴(낙하 8~10회), D2는 붕괴 없으나 초반 낮음; 걸음 맞춤 D0M은 중반 일시 하락 후 회복. CIC: D1·D2·D0M 모두 서서히 D0보다 낮음. 라운드 간 방향 일관성 cos_prev는 ToN·CIC의 D0에서도 높음(0.8~0.9).

## 가설과 사전 예측
각 가설은 서로 배타적이지 않다. 판정어는 "부합/불부합/구분 불가"만 쓴다.

**H1 정체 돌파**: N-BaIoT에서 D0는 특정 지점에 정체(plateau)해 있고, 라운드를 가로지르는 누적 방향이 그 정체를 깬다. ToN·CIC의 D0는 정체가 아니라 이미 최적 근처(또는 더 빨리 포화)라 올릴 여지가 없다.
- 예측: (a) D0의 R6~40 AUC 기울기가 N-BaIoT에서 ≈0이고 클라이언트 평균이 낮은 값에 머문다(기존 로그로 가능). (b) 클라이언트별 AUC(`global_auc`는 클라이언트 리스트로 이미 저장됨, `devices` 이름 포함)를 보면 N-BaIoT D0에서 특정 몇 클라이언트만 낮고 D1·D2가 그 클라이언트들을 올린다(기존 로그로 가능). (c) ToN·CIC는 낮은 클라이언트가 없거나 D1이 오히려 그들을 내린다.
- 불부합: N-BaIoT에서 이득이 모든 클라이언트에 고르게 퍼져 있음, 또는 D0 AUC가 R6~40에서 뚜렷이 상승 중.

**H2 라운드 간 방향 불안정(ToN·CIC)**: 모멘텀 누적은 라운드 간 방향이 일관될 때만 도움이 되고, ToN·CIC는 불일관해 해롭다.
- 예측: ToN·CIC D0의 cos_prev가 낮고 N-BaIoT는 높음.
- 기존 로그: ToN·CIC D0L cos_prev = 0.81·0.89(높음) → 이미 불부합 쪽 증거. N-BaIoT cos_prev는 방향 로깅이 없어 미측정(신규 로깅·4런 필요). D1 셀의 guard.cos(Δ와 직전 속도 v의 코사인)는 N-BaIoT·ToN·CIC 모두 기존 D1 셀에 있음(기존 RESULTS_cos 참고, 재분석 가능).
- 판정 규칙: N-BaIoT cos_prev가 ToN·CIC보다 0.2 이상 높을 때만 "부합", 차이 0.1 미만이면 "불부합".

**H3 클라이언트 이질성 차이**: 데이터셋마다 클라이언트 간 델타 정렬도(비IID 정도)가 달라 평균·누적 효과가 다르다.
- 예측: 클라이언트 간 정렬도가 이득과 단조 관계. 기존 로그 대리지표 E(‖평균 델타‖/평균 개별 노름): N-BaIoT 0.85, CIC 0.76, ToN 0.68(이미 있음, 이득 순서와 같음). 직접 지표 pair_cos는 ToN 0.14~0.18, CIC 0.43~0.52, N-BaIoT 미측정(신규 로깅 필요).
- 한계: 3개 데이터셋이라 상관의 근거가 약함(n=3). 정렬도가 높다고 모멘텀이 이득이라는 인과는 설계상 못 가림.
- 판정 규칙: N-BaIoT pair_cos가 CIC·ToN보다 모두 높고(차 ≥0.2) E 순서와 같으면 "부합".

**H4 D2 초반 undershoot(ToN)**: D2의 ToN 손해는 오버슈트가 아니라 시작 속도 v=0, (1−β)=0.1로 초반 걸음이 너무 작은 것이다.
- 예측: D2의 R1~5 AUC가 D0보다 낮고(기존: ToN 94.4~94.9 대 96.6~96.9, 이미 관찰) 걸음 비율 0.4배(이미 관찰), 후반에 격차 축소. 인과 확인에는 편향 보정(v/(1−β^t)) D2 변형 실행이 필요(사후 튜닝이라 일반화 주장에는 못 씀).
- 판정 규칙: 편향 보정 D2의 ToN R1~5 AUC가 D0와 1%p 이내가 되고 R31~40이 D2 대비 +0.5%p 이상이면 "부합".

**H5 손실 지형 민감도(곡률 대리)**: ToN은 같은 걸음에도 검증 손실이 발산하는 날카로운 지형이라 모멘텀이 해롭다(이미 D1 ToN에서 검증 손실 발산 9/10).
- 예측: 라운드별 global_loss(기존 로그에 있음)에서 D1·D0M의 손실 급등이 ToN·CIC에서 크고 N-BaIoT는 작음. 곡률 직접 측정(헤시안 고유값, 방향 도함수)은 신규 코드·실행 필요.
- 불부합: 세 데이터셋의 D0M(걸음만 키움) 손실 급등 크기가 비슷하면.

## 기존 로그로 지금 가능한 것(실행 0)
H1(a)(b)(c), H2의 ToN·CIC·D1 guard.cos, H3의 E 순서, H4의 R1~5 비교(이미 한 것), H5의 global_loss 급등 크기. → 분석 스크립트만 작성, 새 런 없음.

## 새 로깅/실행이 필요한 것과 비용
1. N-BaIoT에 같은 방향 로깅(D0L·D1L·D2L·D0M, run 10, 시드 1234): 4런. H2·H3의 N-BaIoT 쪽을 채우는 유일한 방법. 기존 N-BaIoT D1 run 10과 AUC 재현 점검 가능.
2. 편향 보정 D2 변형 ToN·CIC·N-BaIoT run 10: 3런(+코드 추가). H4 인과 확인; 사후 튜닝이므로 별도 탐색으로만.
3. 클라이언트별 곡률·헤시안 프로브: 코드 필요, 비용 큼 → 후순위.
4. 위 결과가 일관되면 시드·런 수 확대(새 기준 동결 후).
