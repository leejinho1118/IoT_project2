## 2026-11-23 — 동적 모멘텀 (사용자 요청: 리셋이 아니라 β를 검증 MSE로 연속 조절, 방법 1, 마스터 세션 경유)

## 2026-11-23 — 동적 모멘텀 개선 A·B (사용자 승인, 마스터 세션 경유)
- 변형 A(`mse_mda`): β_t=0.9·min(1,M_prev/M_now)^2. 나머지는 직전 동적 구현(`mse_md`)과 동일(후보 평가 2회 후 β_t로 재생성, 최종 모델 재평가 없음).
- 변형 B(`mse_mdb`): `mse_md`로 β_t를 정해 v·글로벌을 다시 만든 뒤 그 최종 모델의 dev MSE를 한 번 더 잼(평가 3회). 최종 MSE > M_prev이면 β_t를 절반으로 줄여 한 번 더 재생성(최대 1회, 재생성 후 재평가 없음). 라운드 기록 `guard`에 β_t(최종), M_prev, M_now, M_final, 반감 여부, 평가 횟수, 평가 시간 저장.
- 셀(각 1런): O4a_ton_s1234, O4a_nbaiot_s1234, O4b_ton_s1234, O4b_nbaiot_s1234 (data_seed 1234 run10 40라운드, η=1, ToN 맞춤 튜닝 없음). 비교는 기존 D0, D1, 가드, 동적 값 재사용.
- 영향: 판정 없음. 동결 문서 미수정.

## 2026-11-23 — 분석 요청: 서버 dev set 구성 / 방향 일치도 가설 (사용자 지시, 마스터 세션 경유; 추가 실험 없음)
1) 서버 dev set (코드와 실제 로딩으로 확인, `src/main_exp.py:106-113`, `dataset_adapter.py::_mk`, `Trainer/global_aggregator*.py`)
- 각 클라이언트의 `dev_normal_dataset`(정상 행만, 공격 없음)에서 최소 길이 min_len만큼 뽑아 이어 붙인 것. 라벨 없음(`dev_label`은 표준화 처리기가 만든 자리표시이고 서버가 AUC에 쓰지 않음). 
- ToN data_seed 1234: 8클라이언트×300행 = 2400행(33특성). N-BaIoT 비IID data_seed 1234: 10클라이언트, 클라이언트 dev 크기 125~1713 중 최소 125 → 125×10 = 1250행(115특성).
- 서버가 계산하는 값: 정상 샘플 재구성 MSE·검증손실뿐. 서버에서 AUC를 계산할 라벨(공격 샘플)은 없다. AUC는 평가용으로 클라이언트 test(정상+공격)에서만 계산(`fast_auc_all`).
2) cos(Δ_t, v_{t-1}) 가능 여부
- 기존 기록(`runs/*/Run_10.jsonl`)에는 Δ_t와 v_{t-1}이 저장돼 있지 않음. 있는 것은 라운드별 `global_disp`(=‖η·v_t‖), `local_disp`, `pair_mean`뿐이라 v_t=β·v_{t-1}+Δ_t의 내적(코사인)을 복원할 수 없음(‖Δ_t‖와 v_{t-1}·Δ_t 둘 다 미지수). 따라서 기존 기록만으로는 구할 수 없음.
- 새로 구하려면 D1 경로(`mse_m`)에 로그 한 줄(cos(Δ_t,v_{t-1}), ‖Δ_t‖, ‖v_{t-1}‖) 추가 후 재실행 필요. 계산 경로는 안 바뀌므로 기존 run10의 AUC와 일치하는지로 재현 확인 가능. 필요 규모는 마스터에 보고(시작 안 함).
