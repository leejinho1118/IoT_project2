# 지속학습 확장 구현

이 폴더는 원본 src 코드와 실행 중인 원본 실험을 변경하지 않습니다.
현재 데이터는 실제 시간·장치 매핑이 없는 준비된 CSV이므로 **모의 유입 시나리오**입니다.
정답을 검증자 대신 사용하는 **정상 여부를 확인할 수 있는 검증자 보조 환경**입니다.
성능 향상을 미리 가정하지 않습니다.

## 구현 범위
- 원본 SAE-CEN, ClientTrainer, MSEAvg를 그대로 호출하며 모델 공유와 전역 두-if 조기 종료 동작도 유지합니다.
- 전용 CPU 프로세스의 CUDA_VISIBLE_DEVICES를 -1로 지정해 원본 GPU 프로세스에 영향을 주지 않습니다.
- 원본은 전역 가중치를 저장하지 않으므로 별도 초기 학습으로 공통 초기 모델을 만들고 비용을 공개합니다.
- 원본 실험과 분할이 다른 독립 비교 실험입니다. 원본 수치와 직접 합산하지 않습니다.
- 특징 115개 전체의 SHA-256으로 전역 중복을 먼저 제거하고 고유 행 ID와 분할을 저장합니다.
- normal은 40/10/40/잔여로 초기 학습/검증/서버 개발/기존 정상 평가로 나눕니다.
- test_normal은 40/20/잔여로 신규 후보/업데이트 검증/미래 정상 평가로 나눕니다.
- abnormal은 20/40/잔여로 신규 후보/기존 공격 평가/미래 공격 평가로 나눕니다.
- 후보 전체를 검증합니다. 이상 점수는 기록하지만 실제 정답으로 취급하지 않습니다.
- 정상만 재학습에 사용하고 공격·불확실은 routing.json에 보관합니다. 평가 라벨은 학습이나 임계값 선택에 쓰지 않습니다.
- 초기 입력 스케일러를 고정합니다. 각 방식의 정상 학습 자료로 CEN을 다시 적합하며, 초기 정상 검증 점수의 95백분위수 규칙으로 임계값을 다시 계산합니다.
- 재학습 없음 / 신규 정상만 / 신규 정상+리플레이를 동일 초기 모델·참여 순서·최대 에포크와 표본 예산으로 비교합니다.
- 리플레이는 초기 정상의 최대 128개/클라이언트 고정 보관. 매 갱신 학습 길이를 신규 정상 길이와 같게 하고 최대 25%를 리플레이로 대체합니다. 실제 조기 종료 스텝 수는 기록합니다.
- 갱신은 유입 단계마다 수행하며 모든 클라이언트의 검증 정상 최소 수 조건을 만족하지 못하면 해당 단계 업데이트를 보류합니다.
- 동일 평가 세트의 단계별 결과는 적응 추적용이며 독립 최종 일반화 주장에는 새 자료가 필요합니다.

## 실행
프로젝트 루트에서:

```powershell
.\.venv\Scripts\python.exe continual/test_protocol.py
.\.venv\Scripts\python.exe continual/experiment.py --profile smoke --device cpu --run-id smoke_v3
```

smoke는 클라이언트 4개, 원본 역할별 최대 120행, 로컬 2에포크, 전역 최대 2라운드, 유입 2단계, 시드 1개인 구현 검증입니다.
전체 성능 실험으로 해석하지 않습니다. smoke 검증자는 ID 기반 10% 불확실 응답도 모의합니다.
full은 50클라이언트 전체 자료(중복 제거), 최대 100에포크·20라운드, 유입 3단계·5시드입니다.
원본 complete/exit_code=0과 결과 30개가 확인되기 전에는 full 또는 추가 GPU 실행을 거부합니다.

```powershell
.\.venv\Scripts\python.exe continual/experiment.py --profile full --device cuda --run-id full_v1
```

출력은 continual/output/<run-id>에 분리됩니다. 완료 실행은 재실행을 건너뛰고 미완료 디렉터리는 덮어쓰지 않습니다.
실패를 조사한 뒤 새 run-id로 수행하세요. 중간 클라이언트 자동 재개는 현재 추가하지 않았습니다.
결과에는 기존/신규 FPR·TPR·클라이언트 평균 AUC, 추가 학습 시간, 리플레이 수·특징 메모리, 예측 CSV와 스케일러·CEN·임계값·모델 가중치 번들이 포함됩니다.


유입 검증 결과는 세 방식에 동일하게 고정합니다. 각 방식은 매 갱신 직전에 현재 모델로 해당 후보를 다시 탐지해 detections_before_update.json에 기록하지만 예측 자체를 정답으로 삼지는 않습니다. 전체 실행은 원본 결과 30개의 구조·값·참여 조건 검증도 통과해야 시작합니다.


CSV 파싱 라이브러리 버전에 따라 마지막 자리 부동소수점 값과 정확 중복 개수가 달라질 수 있습니다. full_prepare_v1은 학습용 pandas 3.1.0 / numpy 2.5.4의 값으로 고유 벡터 145,401개(원본 148,254행)를 보존했습니다. 문서용 런타임의 기존 146,017개와 합산하거나 같은 감사 정의로 비교하지 않습니다. 원본 CSV 파일은 변경하지 않았습니다. training_runtime_feature_audit.json과 canonical_feature_audit.json에 각 환경 검사를 보존합니다.

독립 추론: infer.py --bundle <detector_bundle.pt> --client 1 --input <헤더 없는 115열 CSV> --out <새 CSV 경로>. 정답 열은 사용하지 않습니다. smoke_v3/standalone_inference_validation.json에서 직렬화 일관성을 확인했습니다. 상세 구현·검증 상태는 IMPLEMENTATION_STATUS.md를 참고하세요.

최신 통합 검증은 smoke_v4입니다. 세 비교군은 초기 모델과 같은 장치를 유지하고 no_update는 초기 가중치·평가 지표까지 동일함을 검사합니다. CUDA 경로는 원본 완료 후 별도 짧은 smoke 검증을 통과시킨 다음 전체 비교를 시작합니다. 실행 상태에 Python·PyTorch·pandas·numpy 버전과 확장 소스 해시도 기록합니다.
