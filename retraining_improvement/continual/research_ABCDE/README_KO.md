# FedMSE A~E 순차 개선 연구

20222038 이진호 / 2026-11-14

## 위임된 작업

각 안마다 실제 재학습 -> 독립 검증 -> 개발 결과 분석 -> 다음 안의 구성 결정 -> 개별 PDF 보고서를 작성한다. A 한 번으로 멈추지 않고 E까지 진행한다. 기존105개 V2 결과는 출발 문제의 근거로 보존하고, A~E는 새 공통 개발 분할에서 각각 새로 재학습한다.

| 안 | 실제 다른 방향 | 앞선 분석의 반영 |
| --- | --- | --- |
| A | 무작위 보관128개, 25% 리플레이 | 같은 초기 모델·분할의 기준 |
| B | 리플레이를50%로 강화 | 선행 V2에서 관찰한 기존 성능 저하에 대응 |
| C | farthest-first 정상 다양성 보관 | A/B 중 개발 점수가 높은 구성의 비율을 계승 |
| D | 이전 개발 정상 복원 오차에 따라12.5~75% 비율 조정 | A~C 중 개발 점수가 높은 구성에서 출발 |
| E | 개발 점수와 기존 AUC 한계를 통과할 때만 배포, 아니면 이전 버전으로 복구 | A~D 중 개발 점수가 높은 구성에서 출발 |

## 실행 규모와 비교 조건

실제 full은 모든 안에서50클라이언트·5시드·3단계·최대100로컬 에포크·20전역 라운드다. 총75개 학습/개발 기록과 초기 모델 포함80개 최종 평가를 남긴다. 초기 전역 모델은 기존 V2에서 별도로 학습해 저장한 공통 모델이며, 원본 로컬model.cpt를 전역 모델로 쓰지 않는다. 원본 SAE·MSEAvg·공유 모델 순차 학습·두 if 조기 종료를 유지한다. 모든 안은 같은 시작 가중치, 입력 scaler, 고정[-20,20]포화, 참여 순서, 표본 수 예산을 사용한다. 조기 종료로 실제 스텝 수는 달라질 수 있어 함께 기록한다.

## 개발과 최종 평가

기존 A/B 정상 검증 풀을 로컬 조기 종료40%/임계값30%/방향 선택30%로 분리하고, 후보 공격 일부를 개발 평가 전용으로 보류한다. E의 개발 선택이 selection_frozen.json에 고정될 때까지 최종 보류 특징을 추출하지 않고 평가하지 않는다. 이후 저장된 scaler·가중치·CEN·임계값을 그대로 평가한다.

중요한 한계: 공통 초기 모델의 과거 조기 종료에는 기존 검증 풀 전체가 사용됐고, 최종 보류 풀도 앞선 V2에서 이미 결과를 본 같은 데이터셋이다. 그러므로 이번 안 내부에서는 평가를 잠그지만 완전히 새로운 외부 확인 실험이라고 주장하지 않는다. CEN 정상 기준도 안별 학습 자료로 재적합하므로 순수 가중치 망각 효과만 분리한 실험은 아니다. 모의 특징 분포 변화이며 실제 시간·기기 드리프트가 아니다.

## 점검 위치

full 실행은 output/campaign_full_v1 아래에 저장한다.

- status.json: 현재 안·시드·단계, 완료한 안 목록
- A~E/policy.json: 개발 결과로 정한 실제 구성
- A~E/development_results.json, analysis.json: 측정 및 분석
- A~E/validation.json: 예측·혼동행렬·AUC·학습 ID·예산·번들·게이트 검사
- A~E/next_policy.json: 분석 뒤 다음 방향
- reports/A_Plan_Report.pdf ... E_Plan_Report.pdf: 안별 연구 보고서
- selection_frozen.json: 최종 평가 개방 전 고정한 선택
- final_summary.json 및 final_summary.csv: 공통 최종 비교
- complete.json: A~E와 모든 검증·보고서 완료 여부
- FedMSE_ABCDE_Research_Package.zip: 코드·계획·분석·PDF·분할 근거, 대용량 모델/CSV 제외

`run_campaign.py`가 이 순서를 직접 수행하므로 채팅 응답 이후에도 단일 백그라운드 프로세스가 A~E를 연속 진행한다. 실패하면 상태와 로그를 보존하고 멈추며 기존 결과를 덮어쓰거나 무조건 처음부터 다시 실행하지 않는다. 효과가 없는 안도 삭제하지 않는다.
