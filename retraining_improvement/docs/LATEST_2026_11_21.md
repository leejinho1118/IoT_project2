## 실제 완료 결과

87개 본 실행, 1,242개 최종 평가 기록을 검산했다. 주 비교는 고정 FedMSE / 신규 정상만 재학습 / 신규+기존 정상 리플레이이며, 검증 게이트·정상 전용 선택·증류·정렬·후보 25% 검증·오승인 5%·학습 예산 민감도를 추가했다.

같은 로그 전처리 조건의 마지막 유입 단계, 5시드 평균 신규 AUC:

| 자료 | 고정 | 신규 정상만 | 리플레이 |
|---|---:|---:|---:|
| N-BaIoT 원자료 | 0.9836 | 0.9767 | 0.9816 |
| RT Thing → MQTT | 0.6592 | 0.9187 | 0.9187 |
| RT MQTT → Thing | 0.5826 | 0.9167 | 0.9026 |

외부 패턴 전환에서는 재학습 이득이 있으나 원자료에서는 보편적 개선이 없었다. 검증 게이트/증류/정렬의 우월성도 지지되지 않았다. Thing→MQTT에서 리플레이 SSH 공격 탐지율은 1.18%(보류 34개, 5시드 평균)에 그쳐 실사용 또는 투고 준비 완료로 해석할 수 없다. 리플레이는 사후 실용 후보이며 사전 주 방법 `safe_new`를 바꾸지 않았다.

원 논문 표의 숫자와 직접 비교한 결과가 아니다. 원본 30개 재현 실행과 이 확장 실험은 분할·전처리·예산이 다르다. N-BaIoT 100epoch/20round 민감도 3시드는 시간 추정으로 미실행했고 완료 수에 넣지 않았다.

## 코드와 시연 흐름

`continual/overnight_2026_11_21/` 안의 `study_data.py` → `run_study.py` → `federated_core.py` → `study_metrics.py`가 신규 후보 탐지, 검증 정상 선별, 재학습과 평가를 구현한다. `run_objectives.py`, `run_normal_gate.py`, `run_approval_study.py`는 별도 연구 조건이다. `verify_*.py`는 입력 ID·공통 초기 가중치·참여 순서·예산·판정 기준 계보를 검산한다.

실행은 원본 저장소를 덮어쓰지 않는 새 출력 ID로만 수행한다. 이 브랜치를 내려받아 `run_followups_*.py`를 실행해도 과거 야간 작업이 자동 복구되는 것은 아니다. 과거 실행 관리자에는 고정된 당시 기한과 출력 ID가 있으므로 보존된 프로토콜/설명용 코드로 읽는다.

이 저장소에는 원시 특징 데이터, 모델 번들, 행별 예측 CSV, 역할별 ID gzip, 가상환경, 대용량 로그를 넣지 않았다. 기록은 로컬 `C:/Users/dlwls/LocalProjects/fedmse`에서 검증한 결과의 이식본이며, 전체 재학습에는 공식 UCI 442/942 자료와 원본 FedMSE 가공 자료, 새 준비 경로가 필요하다. 분할 생성 규칙·자료 해시·구현 환경은 각 `protocol_frozen.json` 및 `study_environment_versions.json`에 있다. 정답 라벨을 검증자로 대신한 환경이고 실제 시간 드리프트나 물리 호스트 전이를 입증하지 않았다.

최신 파일 해시는 `LATEST_2026_11_21_MANIFEST.json`, 이전 역사 파일 해시는 `SOURCE_MANIFEST.json`으로 확인한다. 과거 중간 status 스냅샷보다 최신 `evidence/overnight_2026_11_21/delivery_validation.json`을 완료 판단 기준으로 쓴다.
